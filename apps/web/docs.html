Skill

Adds a SKILL.md to your project so any AI agent (Claude Code, Cursor, Windsurf, Codex) discovers and uses aired automatically. This is the recommended path.

npx skills add progrmoiz/aired -g
  • -g installs the skill user-globally (under ~/<agent>/skills/) so it works across all projects.
  • The skills CLI auto-detects which agent is running it and targets that agent.
  • Powered by skills.sh.

CLI

Publishes a file or directory and prints the URL. Inlines CSS, JS, and images automatically. Pipe-friendly.

npx aired dashboard.html

Common flags

FlagEffect
--ttl <dur>Expiry: 1h, 24h, 7d, 30d
--permanentNo expiry
--pin <pin>PIN-protect viewing
-t, --title <title>Custom page title
--reads <n>Stop opening after N views
--jsonPrint { url, update_token, expiresAt }

The CLI persists update tokens locally via conf. On macOS that lands in ~/Library/Preferences/aired-nodejs/; on Linux ~/.config/aired-nodejs/.

MCP server

Streamable HTTP at https://aired.sh/mcp. Your AI publishes with publish_html, then reads and changes the page with get_page and set_options, all through the MCP transport. The tools table lists everything.

Claude Code

claude mcp add aired --transport http https://aired.sh/mcp

Cursor · .cursor/mcp.json

{
  "mcpServers": {
    "aired": { "url": "https://aired.sh/mcp" }
  }
}

VS Code · .vscode/mcp.json

{
  "servers": {
    "aired": { "type": "http", "url": "https://aired.sh/mcp" }
  }
}

Windsurf · ~/.codeium/windsurf/mcp_config.json

{
  "mcpServers": {
    "aired": { "serverUrl": "https://aired.sh/mcp" }
  }
}

Codex · ~/.codex/config.toml

[mcp_servers.aired]
url = "https://aired.sh/mcp"

Signed in: connect your account

Add https://aired.sh/mcp/account as a custom connector (Claude, ChatGPT, Cursor, VS Code and any client that supports MCP sign-in). The app opens aired, you sign in and choose Allow, and the server works as your account: publish_html pages belong to you, get_page and set_options work on your pages without a token, and list_pages, update_page, delete_page and get_account become available. It can't see your keys or billing, or delete your account.

claude mcp add aired --transport http https://aired.sh/mcp/account

Signed in with an API key

For CI or clients without MCP sign-in, add your API key as a header instead (on /mcp or /mcp/account). Without a key or a sign-in, /mcp offers anonymous publish_html, get_page and set_options with a page's update_token, and send_feedback.

{
  "mcpServers": {
    "aired": {
      "url": "https://aired.sh/mcp",
      "headers": { "Authorization": "Bearer aired_sk_..." }
    }
  }
}

STDIO bridge (any client)

{
  "mcpServers": {
    "aired": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://aired.sh/mcp"]
    }
  }
}

Tools

Every tool returns its result twice: as text, and as structuredContent matching the tool's outputSchema, so an agent can read url, id or expires_at without parsing prose.

ToolWho can use itWhat it does
publish_htmlAnyonePublish HTML and get { id, url, update_token, expires_at, claim_url }. Pass id and update_token to replace a page's HTML.
get_pageThe owner, or anyone with the page's update_tokenTitle, URL, size, views, view limit, expiry, project, and whether a PIN is on (never the PIN).
set_optionsThe owner, or anyone with the page's update_tokenChange the PIN (null removes it), ttl_seconds or permanent, view_limit and title without sending the HTML again. Send only what should change.
send_feedbackAnyoneTell the aired team about a bug, friction or an idea, with an impact (blocked, worked_around, minor). Returns an id to pass on to the user. Never send page HTML.
list_pagesSigned inYour pages, newest first, with a cursor.
update_pageSigned inReplace the HTML of your page by id, no token.
delete_pageSigned inDelete your page for good.
get_accountSigned inPlan, limits, renewal and an upgrade link for a person to open.

The local server (npx aired --mcp) has publish_html (which also takes a file_path or a folder), get_page, set_options and send_feedback. It signs in with aired login or AIRED_API_KEY.

Tool: publish_html

Inputs:

{
  "html":         "string, required, <= 2 MB",
  "title":        "string, optional",
  "ttl_seconds":  "number, optional (default 604800 = 7 days)",
  "permanent":    "boolean, optional",
  "pin":          "string, optional",
  "update_token": "string, optional, with id to update",
  "id":           "string, optional"
}

Returns { id, url, updated, update_token, expires_at, owner, claim_url, upgrade_url } as structured content. Set a view limit or change any of these later with set_options.

HTTP API

No SDK, no auth. POST your HTML and get a URL back.

curl -X POST https://aired.sh/api/publish \
  -H "Content-Type: application/json" \
  -d '{"html": "<h1>Hello</h1>"}'

Response:

{
  "url": "https://aired.sh/p/a1b2c3d4e5",
  "update_token": "at_...",
  "expiresAt": "2026-05-16T12:00:00.000Z"
}

Endpoints

MethodPathDescription
POST/api/publishCreate a page. Returns { id, url, update_token, expiresAt }. Also updates if id + update_token are in the body.
PUT/api/pages/:idUpdate by update_token in the JSON body.
DELETE/api/pages/:idDelete by Authorization: Bearer <token> header.
GET/api/pages/:idPublic metadata: { id, title, size, readCount, expiresAt }. No auth.
GET/api/pages/:id/detailsThe owner's view: { id, url, title, size, readCount, reads, hasPin, permanent, createdAt, expiresAt, project }. Never the PIN. Signed in as the owner, or the page's token in X-Update-Token (or Authorization: Bearer).
PATCH/api/pages/:idChange settings without the HTML: title, pin, ttl or permanent, reads. Same credentials as PUT. Returns the details plus changed.
POST/api/feedbackBody { kind, message, impact?, page_id?, tool? }. Feedback about aired itself; works without signing in, 10 an hour. Returns { id, message }.
GET/api/statsAggregate counts: publishes, views and views per country. No page titles.
GET/api/me/analyticsPro, signed in or with an API key. ?range=7|30|90 (default 30) and &offset=N to step back whole windows, within the last 90 days. Views per day, the total for the window before, the busiest day and its top referrer, and countries, referrer sites and pages across your pages, busiest first (up to 50 each). /api/me/analytics/pages/:id is the same for one of your pages. Free accounts get 402 with code: "plan_limit" and an upgrade_url.
GET/api/favicon/:hostSigned in. The icon of a site that sent views, from the signed URLs in an analytics report's icons field. aired fetches it once and keeps it; a site without one gets a 404.
POST/api/reportBody { id, category?, reason, contact? }. id is a page ID or URL; category is one of spam, phishing, malware, illegal, other. Flags a page for abuse review. Or use the report form.
GET/og/:idOpen Graph image for the page: a 1200×630 screenshot taken after each publish or update, or a generated title card for pages with a PIN or a view limit, pages over 1 MB, and until the screenshot is ready.
GET/p/:idPublic viewer for a published page.
POST/p/:id/verify-pinSubmit a PIN to view a protected page.

Request body — POST /api/publish

{
  "html": "<!doctype html>...",   // required, max 2 MB
  "title": "My dashboard",        // optional, auto-extracted from <title> if omitted
  "ttl": 604800,                  // optional seconds (default 604800 = 7 days)
  "permanent": false,             // optional, true = no expiry (overrides ttl)
  "pin": "1234",                  // optional, viewer must enter to view
  "reads": 10,                    // optional, stop opening after N views

  // To update an existing page in one call, also include:
  "id": "a1b2c3d4e5",
  "update_token": "at_..."
}

Request body — PUT /api/pages/:id

{
  "html": "<!doctype html>...",   // required
  "title": "Optional new title",  // optional
  "update_token": "at_..."       // required (or send Authorization: Bearer)
}

Request body — PATCH /api/pages/:id

{
  "title": "New title",           // 1–200 characters, or null to clear
  "pin": "4821",                  // 4–64 characters, or null to remove the PIN
  "ttl": 86400,                   // seconds from now, 60 to 31536000 (a year)
  "permanent": true,              // or false: expires 7 days from now. Not with ttl
  "reads": 50,                    // view limit, 1 to 1000000, or null to remove it
  "update_token": "at_..."        // unless you're signed in as the owner
}

Send only the fields that should change. Unknown fields are refused, so a typo fails loudly instead of doing nothing.

Update via curl

curl -X PUT https://aired.sh/api/pages/a1b2c3d4e5 \
  -H "Content-Type: application/json" \
  -d '{"html":"<h1>v2</h1>","update_token":"at_..."}'

Delete via curl

curl -X DELETE https://aired.sh/api/pages/a1b2c3d4e5 \
  -H "Authorization: Bearer at_..."

Auth

  • Publishing is anonymous — no API key required. With an API key, pages go to your account.
  • Every publish returns an update_token. It is the only credential for that page.
  • PUT takes the token in the JSON body as update_token, or as an Authorization: Bearer <token> header.
  • DELETE takes the token as Authorization: Bearer <token> header, or as update_token in a JSON body (use the body when Authorization carries an API key).
  • POST can act as update when id and update_token are both in the body.
  • Lose the token and you can't mutate the page (you can still publish a fresh one).
  • Adding a page to your account (aired claim, a claim link or the dashboard) replaces its token. The old token stops working everywhere it was shared, and the claim response returns the new one; the CLI stores it for you. Signed in, you can also update or delete your own pages without a token.

API keys (CI and agents)

Create a key under API keys in your dashboard (up to 5; each is shown once). Send it as Authorization: Bearer aired_sk_… and the request runs as your account: pages are yours, permanent by default, and use your plan's limits. You can update or delete your own pages with the key alone, no update token. A key can't create keys, open billing or delete the account: those need the website. Revoke it from the dashboard and it stops working on the next request.

Sign out everywhere (under Account in your dashboard) ends every session of your account: other browsers, CLI logins and connected MCP apps. API keys keep working until you revoke them. Deleting your account does the same and deletes your keys.

curl -X POST https://aired.sh/api/publish \
  -H "Authorization: Bearer $AIRED_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"html":"<h1>Build report</h1>"}'

The CLI and the local MCP server read AIRED_API_KEY from the environment:

# GitHub Actions
- run: npx aired publish report.html
  env:
    AIRED_API_KEY: ${{ secrets.AIRED_API_KEY }}

Errors

All errors from /api/* are JSON: { "error": "<message>" }, sometimes with a machine-readable code.

StatusWhen
400Invalid JSON body, missing html, validation failed, or the page is too large: over 2 MB anonymously (or whenever billing is off), over 10 MB on any plan.
401Missing credentials where they're required, or an API key that's invalid or revoked (a bad key is never treated as anonymous).
402code: "plan_limit": signed in on Free with billing on, and the request needs Pro (a page of 2–10 MB, or more publishes than Free allows). Includes limit and an upgrade_url for a person to open.
403update_token does not match the page, the page isn't in your account, or the action needs the website (API keys, billing and account deletion can't be done with a CLI token, an API key or a connected app).
404Page id does not exist, the page expired, or the API path doesn't exist.
409Conflict, with a code: key_limit (already 5 API keys), or billing state such as already_pro.
410Page reached its view limit (reads).
422The page looks like spam or phishing and wasn't published.
429Rate limit: 5 publishes an hour per IP anonymously, 30 an hour signed in on Free (402 when billing is on), 500 a day on Pro.
500 / 502Something failed on our side or at the payment provider. Retry, and report it if it persists.
503A dependency is briefly unavailable (storage, the database, or a sign-in provider). Retry shortly.

PIN protection

Pass pin when publishing. The viewer at /p/:id shows a PIN form before serving the HTML.

Submit a PIN

curl -X POST https://aired.sh/p/a1b2c3d4e5/verify-pin \
  -H "Content-Type: application/json" \
  -d '{"pin":"1234"}'

On success, the server sets an HttpOnly, SameSite=Strict cookie scoped to /p/:id with a 1-hour TTL — subsequent loads are pass-through until it expires.

Limits

Max page size2 MB (Free), 10 MB (Pro)
Publishes5 an hour per IP anonymously, 30 an hour signed in on Free, 500 a day on Pro
Default TTL7 days
Max TTLpermanent

Self-hosting

aired runs as one Cloudflare Worker: KV for page records and accounts, R2 for the HTML, D1 for accounts, billing, API keys and sign-in, and Workers Rate Limiting bindings for flood guards.

  • Clone progrmoiz/aired and run pnpm install && pnpm run build.
  • Create a KV namespace, an R2 bucket and a D1 database (wrangler d1 create aired), and put their IDs in apps/worker/wrangler.toml. The KV id goes in twice: PAGES_KV and OAUTH_KV share one namespace. Replace or remove the [[routes]] entries for aired.sh with your own domain. The rate-limit bindings ([[ratelimits]]) and the Browser Rendering binding for link-preview screenshots ([browser]; OG_SHOT_DAILY_SECONDS caps its daily time, 0 turns it off) need no setup.
  • Set the secrets: SESSION_SECRET (32+ random characters), SESSION_VALID_SINCE (an ISO date; sessions, API keys and MCP connections created before it stop working), GITHUB_CLIENT_ID and GITHUB_CLIENT_SECRET (a GitHub OAuth app whose callback is <your origin>/auth/callback), and SITE_ORIGIN if you're not on aired.sh. A few links in MCP replies still say aired.sh. Billing (BILLING_ENABLED, STRIPE_*) and WorkOS sign-in (WORKOS_CLIENT_ID, WORKOS_API_KEY) are optional and stay off until set. apps/worker/.dev.vars.example lists them all.
  • cd apps/worker && npm run deploy applies the D1 migrations, then deploys.
  • Point a custom domain or use the default workers.dev subdomain.
